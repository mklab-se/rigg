# Workstream 2: Promote v2 — translation between environments — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `rigg promote` translates a project's tree from one environment to another: every infrastructure reference is rewritten by binding name, every sibling reference follows the target's physical names, Web API auth carriers are re-derived for the target function app, deployments are checked against the target region, and anything rigg cannot decide becomes a question — shown in a rewiring preview before a byte is written.

**Architecture:** A pure translation engine in `rigg-core::promote` (no I/O beyond the documents and binding tables it is given) produces a `Plan` with per-resource merged documents, a rewiring table, renamed sibling references, unresolved auth carriers and pending questions. The CLI (`commands/promote.rs`) loads trees and bindings, runs the engine, turns pending items into `ask` questions (answers write bindings to `rigg.yaml` and re-run the engine), performs the online steps (Easy Auth lookup, model availability) unless `--offline`, prints the preview, and writes through `Store`. The 1.x pin machinery (`env_pinned`, `resolve_new_webapi_uris`) is deleted; `x-rigg-pin` + `restore_path` survive as the user's escape hatch.

**Tech Stack:** Rust 2024 (MSRV 1.88), serde_json, rigg-diff, the `ask` primitives (ws4a), `infra`/`binding`/`bindings` (ws1), wiremock ARM fake, assert_cmd.

**Spec:** `docs/superpowers/specs/2026-09-09-promote-v2-design.md`; depends on `2026-09-09-environment-bindings-design.md` and `2026-09-09-interaction-model-design.md`.

## Global Constraints

- Branch `rigg-2`; commit after every task with trailer `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- Gate before every commit: `cargo fmt --all -- --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace`.
- Correlation across environments is by logical id = kind directory + file stem; the resource's own `name` is never promoted.
- Translation order per resource: (1) infrastructure references by binding name; (2) sibling references by logical id; (3) keep from target: `name`, `x-rigg-pin` paths (array semantics of `registry::restore_path`), the target's own `x-rigg-pin`; (4) re-derive Web API auth carriers (`authResourceId`, `httpHeaders.x-functions-key`, `x-rigg-auth`) — the source's never cross as-is; (5) everything else from the source.
- Resources only in the target are never touched; nothing is deleted; sidecars promote as content.
- Questions (ids stable): `promote.bind.<from>.<physical>` (text: name for an unbound source reference; default = proposed name; `skip` leaves the reference untouched and reported), `binding.<to>.<name>` (choice: `same` / ARM candidates / `other` text / `skip`), `promote.external.<host>` (confirm: keep verbatim), `promote.deployment.<stem>` (choice: `continue` / `skip` / capacity text). Prefix `promote.` added to `ask::KNOWN_ID_PREFIXES` (`binding.` exists).
- Non-interactive: pending questions → `needs-input` (exit 6), nothing written; `--yes` applies a plan with no pending questions.
- Missing target environment: interactive → run the `env add <to> --like <from>` flow inline, then continue; non-interactive → usage error (exit 2) naming the exact `rigg env add <to> --like <from> …` command. (Ruling: the env-creation question set stays in `env add`; promote does not duplicate it.)
- Preview sections (text and `--output json`): targets line, `Rewiring (bindings)`, `Renamed siblings`, `Resources` (changed/new/unchanged/kept counts + per-resource diff), `Checks`, `Questions` (pending). JSON keys: `targets`, `rewiring[]`, `renamed[]`, `resources{changed[],new[],unchanged[],kept_only_in_to[]}`, `checks[]`, `questions[]`, `dry_run`.
- Online steps (`--offline` skips and reports them as skipped): Easy Auth lookup for new/changed Web API skills; deployment model availability and quota in the target account's region.
- No api-version literals outside the registry.

**Interfaces:**
- Produces:
  ```rust
  pub struct EnvDocs { pub env: String, pub bindings: EnvBindings, pub docs: Vec<Doc> }
  pub struct Doc { pub kind: ResourceKind, pub stem: String, pub physical: String /* name field or stem */, pub body: Value }
  pub struct Rewire { pub path: String, pub binding: String, pub target: Target, pub from: String, pub to: String, pub shared: bool }
  pub struct Renamed { pub path: String, pub kind: ResourceKind, pub stem: String, pub from: String, pub to: String }
  pub enum AuthCarrier { Kept, Stripped { path: String /* skills[i] */, used_key: bool } }
  pub struct Item { pub kind: ResourceKind, pub stem: String, pub target_name: String, pub is_new: bool, pub before: Option<Value>, pub merged: Value, pub rewired: Vec<Rewire>, pub renamed: Vec<Renamed>, pub auth: Vec<AuthCarrier>, pub pinned: Vec<String> }
  pub enum Pending {
      UnboundInSource { kind: ResourceKind, stem: String, path: String, target: Target, physical: String, proposed_name: String },
      MissingInTarget { binding: String, binding_type: Option<BindingType> /* None = implicit target */, source_physical: String, used_by: Vec<(ResourceKind, String, String)> },
      External { host: String, used_by: Vec<(ResourceKind, String, String)> },
  }
  pub struct Plan { pub from: String, pub to: String, pub items: Vec<Item> /* changed + new + unchanged, classified by `change()` */, pub kept_only_in_to: Vec<(ResourceKind, String)>, pub pending: Vec<Pending> }
  impl Item { pub fn change(&self) -> Change /* New | Changed | Unchanged via rigg_diff semantic eq on (before, merged) with key "name" */ }
  pub fn translate(source: &EnvDocs, target: &EnvDocs) -> Plan;
  pub fn rewiring_table(plan: &Plan) -> Vec<(String /*binding*/, Target, String /*from*/, String /*to*/, bool /*shared*/, usize /*refs*/)>;
  ```
  Rules inside `translate`, per resource in `source.docs` (sorted by kind then stem):
  1. `merged = source.body.clone()`; strip source-side `x-rigg-pin` and Web API carriers (`skills[].authResourceId`, `skills[].httpHeaders.x-functions-key`, `skills[].x-rigg-auth`) recording `AuthCarrier::Stripped{used_key}` per skill (used_key = uri had `code=` or a key header).
  2. For each `infra::extract(kind, &merged)` ref (in path order): find the source entry `source.bindings.find_physical(Wanted::for target, physical)`; none → `Pending::UnboundInSource` (proposal name via the same kebab rule as learn: `bindings`-free helper `proposed_binding_name(physical)` lives here) and leave the value; some → the target entry `target.bindings.get(name)`; none → `Pending::MissingInTarget` (dedup by binding name; collect `used_by`); some → `RenderTarget { physical: entry.physical_name, arm_id: entry.resolved.arm_id or the declared ARM id value, base_url: declared api URL, source_base_url: source declared api URL, kb_name: (SearchKbMcpUrl) mapped through sibling translation below }` → `infra::render` → set at the concrete path (helper `set_path(&mut Value, concrete_path, Value)`); record `Rewire { shared: from == to }`. `Target::Api` with no source binding → `Pending::External{host}`.
  3. Sibling references: build `stem→physical` maps for both envs per kind; for each `registry::meta(kind).reference_fields` value equal to a source physical name whose stem exists in the target with a different physical → `rename_reference(kind, &mut merged, to_kind, old, new)` and record `Renamed`; same for `x-rigg-ref` values (`rename_x_rigg_ref(&mut merged, dir, old, new)`) and for the `kb_name` inside `SearchKbMcpUrl` (used in step 2's `RenderTarget.kb_name`: the target physical of the kb stem when known, else the source kb name).
  4. Target keep: if a target doc with the same (kind, stem) exists: `merged["name"] = target.name`; for each path in target's `x-rigg-pin` → `registry::restore_path(&mut merged, &target.body, path)`; restore the target's `x-rigg-pin` itself. Then re-apply the target's existing Web API carriers per skill index when present (`authResourceId`/header/`x-rigg-auth` from `target.body["skills"][i]`), marking those `AuthCarrier::Kept`.
  5. `Item.is_new = target doc absent`; `before = target.body`.
  `kept_only_in_to` = target (kind, stem)s absent from the source.

  7. Hints per spec §5.
